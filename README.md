# claude-mods

Claude Code mods (plugins built on function hooks). The repo is also a plugin marketplace: `.claude-plugin/marketplace.json` lists every mod.

[Version française](README.fr.md)

## Install

Add the marketplace once, then install the mods you want:

```bash
claude plugin marketplace add Akeuuh/claude-mods
```

```bash
claude plugin install jev-guard@claude-mods
```

Or every mod at once:

```bash
for m in jev-guard jev-compact jev-route ask-jev-file ask-jev-files ask-jev jev-hud branch-notes; do claude plugin install "$m@claude-mods"; done
```

Inside a session, `/plugin marketplace add Akeuuh/claude-mods` then `/plugin` to browse and install. `--scope project` on either command shares the install with a repo's collaborators through `.claude/settings.json`.

The jev mods need an API key in Claude Code's environment: see [jev/README.md](jev/README.md).

Update to the latest release:

```bash
claude plugin marketplace update claude-mods
```

```bash
claude plugin update jev-guard@claude-mods
```

From a local clone (Claude Code then reads the mods in place; after a build, `/reload-plugins`):

```bash
claude plugin marketplace add /path/to/claude-mods
```

## The `jev` family

The pi extensions from [ten-levels-of-jev](https://github.com/disler/ten-levels-of-jev) (levels 6 to 10) ported to mods. `jev/lib/` is an adapted copy of its `src/core` and `src/levels/level06..10`: `decide` and the file system are parameters, the Node transport is removed.

| Mod | What it does |
|---|---|
| `jev-guard` | Jev blocks irreversible or destructive `Bash`, `Write`/`Edit` outside the repo or containing a secret, and flags `Read`/`Bash` results that contain instructions |
| `jev-compact` | At the end of every turn, Jev judges whether to compact; `should_i_compact` and `compact_now` tools; on compaction, Jev picks where the live work starts |
| `jev-route` | Jev scores how demanding each prompt is (5 levels) and picks the model and effort it goes out on; a subagent with no model of its own is judged on its task. Moves down only once the context is small or after two easier prompts, to spare the prompt cache. `/jev-route auto\|pin\|floor\|ceil\|status`; a `/model` change turns it off until `auto`. Tiers in `~/.config/claude-mods/jev.json` (see [jev/README.md](jev/README.md)) |
| `ask-jev-file` | `ask_jev_file_bool`, `_choice`, `_score`: a typed question about a file without reading it into context |
| `ask-jev-files` | `ask_jev_files` on many files in parallel, then `pick_first_file` |
| `ask-jev` | `ask_jev` on any situation (files, a command's output, the agent's state), with spend tracking |
| `jev-hud` | A band above the prompt: a spinner while Jev thinks, each intervention in colour (⛔ blocked, ⚠ flagged, ✓ ok, ◆ answer), calls, mean latency and spend. **Pause** button (`p` when the band has focus) sets `JEV_PAUSED=1` for the process, and every jev mod stops calling Jev until **Resume**. While paused, `jev-guard` lets everything through. Moves the `jev · …` transcript lines to the debug log |

Claude Code needs `OPENROUTER_API_KEY` or `TYPESAFE_API_KEY` in its environment (`JEV_BACKEND` forces one of them). `JEV_LEVEL_CONFIG` (JSON) sets the `jev-guard` gates (`{"gates":["A","B"]}`) and the `jev-compact` thresholds (`{"lines":{"notice":80000,"recommend":120000,"request":160000}}`).

Each Jev decision shows as a greyed line in the transcript, invisible to the model, and is also written as JSON to the debug log (prefix `jev-event `): that is what `jev-hud` reads.

## The `notes` family

| Mod | What it does |
|---|---|
| `branch-notes` | One markdown file of notes per git branch (goal, decisions, constraints, state) in `~/.claude/branch-notes/<repo>/<branch>.md` (`/` written `%2F`), shared by every worktree of the repo. The notes ride in the system prompt, so they survive a compaction; the model fills them with the `note_add` tool; a `git checkout`/`switch` in `Bash` reloads the branch. No notes on `main`, `master`, `develop` |

`/notes` shows the notes of the branch, `/notes all` lists those of the repo, `/notes pane` opens a live pane, `/notes add <section> <text>` appends (`objectif`, `decisions`, `contraintes`, `etat`), `/notes edit` opens the file, `/notes prune` lists the notes of branches that no longer exist and `/notes prune --yes` deletes them.

## Layout

```
.claude-plugin/marketplace.json   the mod list, one entry per mod
scripts/build.ts                  bundles each <family>/<mod>/src/register.ts(x) into hooks/register.js
<family>/
  lib/                            code shared by the family's mods
  <mod>/
    .claude-plugin/plugin.json    name, version, description, author, license
    hooks/hooks.json              { "modules": ["./register.js"] }
    hooks/register.js             generated by the build, committed (this is what Claude Code loads)
    src/register.ts               the mod's source
    register.test.ts              run by `claude plugin test`
    LICENSE                       shipped with the mod, since it is installed on its own
```

A hooks module can only import files from its own plugin and runs without Node: the build inlines the family's `lib/` into each `register.js`. All system access goes through `$` (`$.fs`, `$.http.fetch`, `$.env`, `$.process`).

New mod: a `<family>/<mod>/` folder with the files above, then an entry in `marketplace.json`.

```bash
bun run build
```

## Release

Bump `version` in every `plugin.json`, add a section to [CHANGELOG.md](CHANGELOG.md), merge to `main`, then tag:

```bash
git tag v0.1.0 && git push origin v0.1.0
```
